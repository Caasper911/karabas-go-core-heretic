# Doom для Karabas Go / Mini / Mini G — план

## Исходные данные (обзор 2026-11-18)

- Путь через x86 закрыт: ao486 в XC6SLX25 не влезает, наш next186 — 80186 (Doom нужен 386).
- Готовые порты на софт-CPU RISC-V:
  - **DIY-A586** (piotr_go, XC6SLX9 + SDRAM 32 MB): ядро RISC-V играет Doom; по форуму elektroda ~45 fps после
    аппаратного масштабирования (**не проверено**: страницы форума не открылись, цифра из пересказа поиска).
    Ядро закрытое (платная регистрация), взять нечего. Доказывает лишь, что SLX9 хватает.
  - **smunaut riscv_doom** (ice40-playground + smunaut/doom_riscv): iCE40UP5K, VexRiscv rv32im 25 MHz, QSPI PSRAM 8 MB
    через кэш, WAD в SPI flash, кадр 320x200x8 в SPRAM + палитра, выход 640x480. Без звука. Самый маленький открытый пример.
  - **ulx3s/Hazard3-Doom** (ECP5): Hazard3 40–50 MHz + doomgeneric, кадр в BRAM с двойной буферизацией, SDRAM через кэш,
    IWAD по UART. Без звука, fps не опубликован.
- Плата: XC6SLX25, SRAM 4 MB (2M x16, асинхронная, своя шина), SDRAM 32 MB (16 бит), RP2040 (прошивка, не хост игры).
  Синтезатор MIDI SAM2695 на всех трёх платах; на Mini / Mini G его звук идёт через АЦП PCM1808 в ПЛИС (и дальше в HDMI),
  на Go в топах АЦП нет (проверить в Ф1: звук SAM2695 на Go только аналоговый?).

## Решения пользователя (2026-11-18)

- Вариант A: свой SoC на софт-CPU RISC-V + исходники Doom на C. CPU — на выбор Claude.
- Музыка: OPL2 / OPL3 в ПЛИС **и** MIDI-синтезатор SAM2695 (его звук — захват через АЦП), выбор в OSD.
- WAD грузит пользователь с SD1 (пункт файла в OSD), в ядре WAD нет.

## Решения Claude (пока не подтверждены пользователем)

- **CPU: VexRiscv** (MIT), уже есть готовые Verilog-варианты, тулчейн (xPack riscv-none-elf-gcc 15.2.0-1 в `~/opt`),
  свой быстрый ISS с моделью кэша и Verilator-стенд из core-pico8. Нужен вариант с прерыванием таймера (музыка 140 Гц).
- **Исходники: doomgeneric** (ozkl, e257a09, Chocolate Doom 2.x, GPL-2+): уже есть `mus2mid.c`, `s_sound.c`,
  платформа сведена к нескольким функциям `DG_*`. Музыку OPL берём из Chocolate Doom (`i_oplmusic.c` + `opl/`, GPL-2+)
  со своим драйвером OPL: запись регистров = MMIO в `opl3_fm` (opl3_fpga, LGPL-3, уже в core-tsconf / core-zxuno).
  MIDI: MUS → события MIDI → байты в `kg_midi_tx` → SAM2695.
- **Память**: код, куча (zone) и WAD — в SDRAM; два буфера кадра 320x200x8 — в SRAM (переключение во время гашения);
  I/D-кэши в BRAM. Бюджет SDRAM: WAD до ~20 MB (DOOM2 14.6 MB, Plutonia / TNT ~18 MB) + zone 8 MB + код < 1 MB.
- **WAD через FL** (target 04 LOAD, kind 2): весь файл в SDRAM до старта игры, CPU держится в сбросе. SPI 32 MHz даёт
  предел ~4 MB/s; реальная скорость SD → FPGA не замерена (оценка 5–15 с на DOOM2) — замер в Ф1. Если окажется слишком
  медленно — запасной путь: F-слот (`img_sdc`) с чтением lump-ов по запросу (мгновенный старт, но подгрузка в игре и куча больше).
- Сохранения и `default.cfg` — на SD: через F-слот с образом или `kg_bk_ram` (решить в Ф3).
- Видео: 320x200 → 640x400@70 (как VGA mode 13h) или 640x480@60 с полосами; палитра в BRAM.
- Звук эффектов: микшер в RTL (8 каналов PCM 11 кГц из WAD, громкость / панорама), CPU только запускает каналы.

## Ф0 — замер (go / no-go), без платы

Цель: кадров в секунду в `-timedemo demo1` (DOOM2.WAD, локально в `~/Downloads`, в git не кладём) на реальной модели
памяти. Проход: **не меньше 20 fps** при выбранной частоте (60–80 MHz).

1. doomgeneric для rv32im: сборка, платформа `DG_*` (кадр в память, таймер, без ввода), WAD в памяти.
2. Прогон в ISS (core-pico8 `iss`, модель кэша), `--prof`: где время (ожидаемо `R_DrawColumn`, `R_DrawSpan`,
   `FixedMul` / `FixedDiv` — проверить, не уходят ли в 64-битные хелперы libgcc).
3. Перебор: размеры I$/D$, размещение кода / горячих данных в SRAM против SDRAM, запись кадра без кэша
   (запись столбцами), чтение текстур из SDRAM.
4. Калибровка ISS по Verilator VexRiscv на коротком окне (из дампа ISS), как в PICO-8. Прогоны — секунды;
   долгие только после вопроса.
5. Площадь и Fmax: XST VexRiscv + контроллер SDRAM + OPL3 + микшер, оценка LUT.

Результат Ф0: таблица «fps на конфигурацию» + строка go / no-go.

## Ф1 — Mini G: картинка и управление

SoC (VexRiscv, SDRAM, SRAM-кадры, палитра, HDMI), `kg_mcu2` (HID клавиатура / мышь / джойстик, OSD, FL WAD), запуск
игры с WAD пользователя. Замер скорости FL.

## Ф2 — звук

Микшер эффектов, OPL3 (`opl3_fm`) + драйвер OPL в Chocolate Doom, MIDI в SAM2695 + АЦП (с усилением: в boot-меню он тихий),
OSD «Music: OPL / MIDI / Off».
